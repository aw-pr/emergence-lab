## Harness settings

256×256 grid, channel 0 (Trail), 300 warmup steps, flux gap 6, coverage
threshold 0.1.

**Agent counts are scaled, and that constrains what this sweep can conclude.**
The app pins Physarum to its own compute scale (384² cells, `qualityProfiles.ts`
sets `computeScale: 1` for this sim), and what the dynamics respond to is agents
per cell, not raw agent count. The sweep runs at 256², so every reference count
is scaled by (256/384)² ≈ 0.44: veins 32 000 → 14 000, coral fans 26 000 →
11 500, filigree web 60 000 → 26 500. Swept sets are pinned at 14 000.

The consequence, stated plainly: **this sweep cannot rank the shipped presets on
their agent counts.** It ranks them on sensing geometry with density held at the
app's ratio. Any promotion that amounted to "use more agents" would be an
artefact of the rescaling, not a finding.

## Reading

Autocorrelation is ≥0.96 for every set and every reference — Physarum builds a
coherent network under any parameters it is given, so structure does not
discriminate here. The whole 0.20 spread across the run is carried by entropy
and coverage, i.e. by how much of the frame the network fills and how graded the
trail intensities are.

The top of the ranking is a clean block: **the top six sets are all of the
sensorAngle-60 sets at turnSpeed ≤ 22.5**, and the best set at any narrower angle
is 0.823 (38°/9/12), below all six. Within the angle-60 block turnSpeed leads
(12 → 0.895–0.901, 22.5 → 0.838–0.870) and sensorDistance barely registers —
0.901, 0.897, 0.895 across the whole 5–17 range. Wide sensors with a slow turn
produce a broad, evenly branching mat that fills the frame; the shipped presets
all use narrower sensors (15–38°) and faster turns (14–34°).

That regime is not one of the three shipped presets, and it is not a better
version of any of them — it is a different-looking network. Filigree web already
covers the "fills the frame" end at 0.851.
